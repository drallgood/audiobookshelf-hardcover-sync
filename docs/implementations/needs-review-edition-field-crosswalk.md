# Source Draft Field Crosswalk

This crosswalk covers the read-only source draft returned by
`GET /api/profiles/{id}/edition-drafts/source/{itemID}`. It describes draft
data from Audiobookshelf (ABS) and optional Audnex region discovery. The route
makes no Hardcover requests and does not create an edition or mapping.
[Create request](#create-request) describes how the create route uses the
same values.

| Concern | Draft field | Source and treatment |
|---|---|---|
| Item and mode | `abs_item_id`, `reading_format`, `dry_run` | Item ID and reading format come from the expanded ABS item. `dry_run` reflects the profile's sync setting; this draft route is read-only in either setting. |
| R4: ASIN identity | `source_identifiers.asin`, `confirmed_region`, `region_status`, `audible_identifier_candidate` | `source_identifiers.asin` is the trimmed, bare ABS ASIN, without a region suffix. Audnex confirmation is reported separately: `confirmed_region` is present only when a response returns the exact ASIN being previewed; `region_status` distinguishes `confirmed`, `unknown` after no exact result or a non-retryable lookup failure, `temporarily_unavailable` after a rate limit or transient error, and `not_applicable` when an audiobook has no source ASIN. By default, discovery checks the preferred Audnex region first (US when unset), then the remaining supported regions. The candidate contains the source ASIN and discovered region by default. The optional `audible_identifier=ASIN:region` query previews that corrected identifier in exactly its supplied region and updates the candidate values; consult `region_status` before treating the region as confirmed. The draft never writes `edition.asin` or `book_mappings`. |
| Audible import comparison | `audnexus_record`, `audnexus_comparison` | When Audnexus returns the exact ASIN in a confirmed region, the draft includes its title, subtitle, authors, narrators, series and position, publisher, release date, runtime in seconds, language, and cover URL. Authors, narrators, and series are string arrays; each emitted `audnexus_comparison` field is `match`, `differs`, or `missing`. String values are trimmed and compared case-insensitively; recognized release dates are normalized for display and compared at the coarsest precision provided by either source (year, month, or day), while runtime values are rounded to seconds for comparison, with differences of up to 60 seconds treated as a match. The comparison omits `cover_url` because ABS `media.coverPath` is a server-local path while Audnexus `image` is a URL; both source cover values remain available in their respective records. Comparison tolerances do not alter source or import values. Differences are informational. A missing or temporarily unavailable record is not confirmable. `audible_identifier=ASIN:region` on the GET request previews a corrected ASIN in exactly that region; it does not trigger a region sweep. |
| Sync classification | `book_outcomes[].reason`, `source_asin`, `source_isbn_10`, `source_isbn_13`, `format`, `hardcover_book_id`, `edition_id` | An unmatched audiobook with a usable source ASIN (exactly ten ASCII letters or digits) is `needs_review` with reason `audible_import_available`. The normalized source identifier fields and reading format form the create API's source snapshot; no Hardcover book or edition ID is set, and title/author search is skipped. The mismatch export sets `info.reason` to `audible_import_available`, carries the ABS item ID, and omits `book_id`. |
| ISBN | `source_identifiers.isbn`, `isbn_10`, `isbn_13`, `isbn_10_valid`, `isbn_13_valid`, `corrected_isbn` | The source ISBN is trimmed but otherwise preserved. Candidate ISBNs remove separators and uppercase a trailing `x`. The ISBN parser accepts by shape and reports checksum validity separately; a counterpart is derived only when the source checksum permits it. Ebook drafts include an empty `corrected_isbn` slot. |
| Audiobook metadata | `source_metadata_preview`, `metadata_preview` | Audiobook-only, read-only ABS previews of title, subtitle, author, narrator, publisher, description, language, date, edition format and information, duration, series and position, cover URL, and ISBN fields. `source_metadata_preview` retains source values before Audnex enrichment; `metadata_preview` is the candidate used by the creation flow. Neither is an editable request body. |
| Publication date | `source_metadata_preview.release_date`, `metadata_preview.release_date`, `ebook_candidate.release_date` | `source_metadata_preview.release_date` preserves the ABS `publishedDate`, or `publishedYear` when no date is provided, at its original precision (a year-only source remains `2014`). For a confirmed audiobook identifier, a recognized Audnex release date is normalized to `YYYY-MM-DD` and overrides the ABS date in `metadata_preview`. If Audnex has no usable date or its value is unrecognized, `audnexus_record.release_date` is omitted and `metadata_preview.release_date` keeps the ABS `publishedDate`, then `publishedYear` fallback. An unrecognized non-empty Audnex date adds `audnex_date_unrecognized`; unusable ABS dates produce a warning. Ebook candidates use the ABS date order. |
| Ebook candidate | `ebook_candidate` | Ebook-only candidate with title, subtitle, author, source ASIN, normalized ISBN fields, validity flags, normalized ABS publication date/year, fixed `edition_format: "Ebook"`, and the empty `corrected_isbn` slot. The GET endpoint does not accept candidate edits or create an edition. |
| Eligibility and warnings | `eligible`, `ineligible_reason`, `warnings` | Eligible means a valid ASIN (exactly 10 ASCII letters or digits) or an ISBN accepted by shape is present; a malformed ASIN is kept visible with an `invalid_source_asin` warning but does not count. A bad-checksum ISBN remains eligible when its shape is supported. Author and date gaps are warnings, not eligibility gates. Warning objects contain a code and message; `retryable` is true for temporary Audnex unavailability. |

The response field definitions and warning codes are documented in
[`openapi.yaml`](../openapi.yaml) and are implemented in
`internal/api/handlers_edition_draft.go`. Audnex discovery is implemented in
`internal/api/audnex/client.go`; the normalized comparison fields and statuses
are built by `internal/edition/audnexus_comparison.go`.

## Create request

`POST /api/profiles/{id}/edition-drafts/create` is the only route here that
writes to Hardcover. It refetches the ABS item and rebuilds the same draft
values rather than accepting a submitted draft. For records with a Hardcover
candidate, the book ID comes from the selected needs-review sync result; the
request adds an edition to that book.

| Concern | Request field | Destination and treatment |
|---|---|---|
| Source snapshot | `run_id`, `abs_item_id` | The completed, non-dry-run sync record must still match the refetched item's ID, reading format, title, author, ASIN, and ISBN after trimming and case or ISBN-separator normalization; otherwise the request returns `409` before any Hardcover call. |
| R4: selected-book audiobook identity | `audible_identifier` (optional `ASIN:region`) | For a needs-review record with a selected Hardcover book, the create API uses the book ID in the run record. Without `audible_identifier`, it discovers the source ASIN's region; an unconfirmed region refuses the import. The regional ID is submitted to `upsert_book` (platform 32) with that recorded book ID. It never writes `edition.asin`, uses an `editions.asin` duplicate guard, or falls back to `insert_edition`. |
| **Import by Audible ASIN** | `audible_identifier`, `audnexus_confirmed` | When the run record's reason is `audible_import_available`, the request must include `audible_identifier` in `ASIN:region` form and set `audnexus_confirmed` to `true`. The identifier must match the regional record the user reviewed; its ASIN may differ from the ABS source ASIN when corrected in the draft. The handler refetches ABS and checks the source snapshot, then rereads Audnexus for exactly that identifier and region: an exact miss or different returned ASIN is `409`; a rate limit or transient failure is retryable `503`, with no Hardcover import sent. The import calls `upsert_book` without `book_id`, then verifies the returned book and audiobook edition before saving the local association. A Hardcover identity conflict may happen after the remote import; use returned recovery data with `check-import` rather than resubmitting creation. |
| Audiobook metadata | none | Preview-only. `metadata_preview` in the response is rebuilt from ABS, with the release date from the Audnex region that resolved the submitted ASIN when available. Metadata fields in an audiobook request are rejected. |
| Ebook fields | `title`, `subtitle`, `asin`, `isbn_10`, `isbn_13`, `release_date`, `edition_format` | Each optional value replaces the matching `ebook_candidate` value before `insert_edition` through the format-aware creator (`reading_format_id` 4). A lone ISBN correction also sets its counterpart. At least one ASIN or ISBN must remain. Authors come from the Hardcover book, else an exact ABS author name match; the publisher is an optional exact name match. |
| Local association | none | Saved only after the returned book, edition, and reading format are verified. It records the ABS identifier snapshot and any correction plus the regional ID. An **Import by Audible ASIN** association records the existing provenance value `audible_import_unanchored` and the Audnexus confirmation region and timestamp. |
| Ambiguous-import recovery | `audible_identifier`, `recovery_token` | For an unconfirmed remote result or a verified import whose local save failed, the signed recovery data can be submitted to `check-import`. Responses for imports tied to a selected Hardcover book may include a response-only `hardcover_book_id`; **Import by Audible ASIN** responses omit it, and recovery derives the resolved book from Hardcover's terminal import status or exact regional mapping. The endpoint performs no Hardcover mutation, freshly verifies the audiobook edition, and saves the local association only after confirmation. Retry the status check while pending; do not resubmit create. |
| Immediate read-status resync | `resync` (optional, defaults to `false`) | After creation and association save, syncs this ABS item through the regular per-book path using the verified association. The profile guard and state-file lock remain held; an active full sync refuses either create mode with `409` before mutation. The response reports resync failures separately because the edition already exists. Dry-run profiles are refused before creation or resync. |
